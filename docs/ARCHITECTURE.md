# FreePublish 2.0 — 安全原则与架构

> 从“发布安全知识手册”升级为可运行的 Local-first 多平台发布工作台。保留原项目的 \`01\`–\`05\` 安全经验文档；这些文档是历史参考，可能存在过时的平台时限、规范或平台接口陈述，实际使用以现行官方规则和页面为准。

## 工作流

素材建档 → 平台版本生成（本地规则初稿）→ 风险预检 → 人工确认提示项 → 人工审批 → 打开平台官方创作中心 → 用户手动上传/粘贴/提交 → 人工回填作品链接

- “计划发布时间”仅供本地排期；**不会在所设时间自动发布，也不会向平台创建定时任务**。
- “为所有平台生成版本”只处理文字、标题阈值、标签提取；不是 AI 自动重写、自动剪辑或原创性保证。
- “审核通过”是本机可编辑数据的状态标记，不是平台合规认证，不是组织级不可抵赖电子签名。
- “已发布·人工登记”仅代表操作者自行填写作品链接，系统不访问平台验证链接状态、发布时间或账号。
- 修改后必须重新审核；从备份导入后清除审核/发布状态，防止不可信导入绕过审批。

## 安全边界

1. 不保存账号密码、Cookie、Token、浏览器配置文件。
2. 不注入平台 DOM，不启动浏览器自动点击，不抓包，不调用非公开接口。
3. 视频号尤其只能打开官方创作入口，不能操作其页面或帐号。
4. 发布前的最后确认一定在人手上；没有自动发布任务、守护进程、后台重试。
5. 敏感词预检只给线索，不能代替语义判断、证据核查与法律意见。
6. 所有业务内容数据保存在用户浏览器 \`localStorage\` 中；站点清缓存、切换浏览器或无痕模式会丢。需要定期用“导出备份”保存 JSON 文件；文件名不包含 Token。
7. 导入 JSON 会**替换本地内容库**，先导出一份，再导入。
8. 当前没有多用户权限控制；“审核人”只是备注，不能用于组织级审批。真正团队协作、角色与签名应在服务端版本实现。

## 开源参考（借鉴产品思路，未复制第三方代码）

- [Postiz](https://github.com/gitroomhq/postiz-app)：跨平台工作台、队列与团队协作产品思路（AGPL-3.0，禁止直接复制进当前不同许可证仓库而忽略许可义务）。
- [social-auto-upload](https://github.com/kuloutoussssss/social-auto-upload)：国内平台字段及发布链路参考；本版本主动避免其登录态/网页自动化方案。
- [yuwen-publish-precheck](https://github.com/yuwen-cool/yuwen-publish-precheck)：将关键词扫描视为“线索”，而非最终审核结论。

## 下一阶段

- **P1**：浏览器本地媒体预览、视频尺寸/比例解析、平台适配提醒；批量导出各平台可粘贴发布包。
- **P1**：官方 OAuth/API 的能力矩阵；只接已获授权且确实开放写接口的平台。任何自动发布均另设显式开关和平台级白名单，不沿用当前发布模型。
- **P2**：可选自托管服务端、多成员权限、审批签名、操作日志持久化、审计导出、定时提醒（**提醒 ≠ 发布**）。
- **P2**：AI 改稿辅助作为可选外部插件，默认关闭、不得替用户自动批准或发布。

## 安全回归验收

运行 \`npm test\`：验证权属阻断、AI/商业标识阻断、审批失效、人工登记受控、URL 域名校验、不可信备份失权等。
